# Event update validation — F12

Implemented on 15 October 2026 following [the original review](../SECURITY_REVIEW.md).

`PUT /api/events/:id` no longer forwards `req.body` to Mongoose. The handler
validates the event ID and request before event lookup, creates a new object
containing only typed editable values, and submits a server-constructed `$set`
with `runValidators: true`, `strict: "throw"`, and `upsert: false`.

| Editable field | Accepted value |
|---|---|
| `title` | Nonblank string, at most 200 characters; trimmed |
| `description` | String, at most 10,000 characters; empty clears it |
| `eventType` | `Trip`, `Visit`, `Fasting`, `Feast`, `Mass`, `Meeting`, or `Other` |
| `startDate` | Valid date-only, browser date-time, or ISO timestamp string |
| `endDate` | Valid date string; `null` or empty string clears it |
| `allDay` | Boolean, including `false` |
| `location` | String, at most 500 characters; empty clears it |
| `years` | Array of up to 12 unique integers from 1 to 12; empty is allowed |

Updates must contain at least one field in a plain object. Unknown and protected
fields are rejected with HTTP 400, including `createdBy`, `source`, `calendarKey`,
`generatedYear`, `_id`, timestamps, and `__v`. Client-owned MongoDB operators,
aggregation pipelines, dotted keys, `__proto__`, `constructor`, and `prototype`
are rejected. Typed field validation excludes nested objects/operators even
inside otherwise editable fields. Mixed valid/invalid requests are rejected
in full; no partial write or event update casting occurs. Strings containing
operator-like text remain ordinary text values.

Authorship and generated-calendar identity are preserved for both manual and
generated events. Audit `updatedAt` is still generated by Mongoose. Event types
are shared between the model and validator so their accepted values agree.
The existing verified-user and current-database-role middleware remains in
force: only `admin`, `leader`, `pascal`, and `pamela` can update events. Body and
JWT role claims do not confer permission.

Date validation rejects impossible calendar days and invalid times. Partial
updates are checked against stored start/end dates. The final atomic write
matches those dates as well as the event ID, preventing concurrent partial
date edits from creating a reversed range. A changed/deleted event between
read and write returns HTTP 409; an initially missing event returns 404.
Malformed IDs, invalid payloads, and schema validation errors return safe 400
responses. Database failures return a generic 500 response without internal
diagnostics. No upsert or replacement update is allowed.

The existing edit form already submits only these editable fields and uses
supported date/null/boolean/year values, so it needs no client changes.

## Mongoose casting advisory

The installed and locked backend Mongoose version is **9.11.2**, already beyond
the **9.7.2** fix for the reviewed
[prototype-pollution casting advisory](https://github.com/Automattic/mongoose/security/advisories/GHSA-664h-wqgq-64gw).
No dependency change was needed for this task. The existing dependency regression
test checks the patched casting behavior; the new route validation prevents
untrusted update structures from reaching casting in the first place.

## Validation

`backend/tests/eventUpdates.test.js` adds 13 regression cases covering protected
metadata and mixed updates, operators/pipelines/dotted/prototype payloads, field
types and bounds, successful full and partial edits, preserved metadata, all
four staff roles, optional clearing, date validity/order/races, missing/invalid
IDs, forged roles, role/session revocation, authorization outages, and safe
error responses. Tests assert that rejected payloads never enter Event query
construction or update casting and that `Object.prototype` descriptors remain
unchanged.

Tests exercise Express JSON parsing/routing, JWT validation, and actual Mongoose
query casting/validation. Collection I/O is simulated; no live database records
are changed. Run `node backend/tests/eventUpdates.test.js` for the new cases and
`npm test` for the complete backend/frontend suite, including the existing
dependency casting regressions.

All **15 test files passed** with `npm test`, including the **13 new event-update
regression cases** and the existing prototype-casting dependency checks. Scoped
`git diff --check` also passed. No frontend code or dependency versions changed.
